# CMMS HPS 제품 사양서

> 초안. 이 문서는 제품이 해결할 업무와 사용자 관점의 동작을 정의합니다. API, DB 구조, 설치 절차는 각각 `tech_spec.md`,  `install_guide.md`에서 다룹니다.

## 1. 제품 개요

CMMS HPS는 여러 관리대상회사의 설비와 유지보수 업무를 하나의 시스템에서 관리하는 온프라미스 설비관리시스템입니다. 설비·자재·조직 정보를 기반으로 예방점검·작업오더·작업허가·구매·재고 관리를 통합 추적합니다.

제품의 핵심 목표는 다음과 같습니다.

- 설비 상태와 유지보수 이력을 일관된 업무번호로 추적
- 계획·승인·실행·결과의 흐름을 업무 기록으로 보존
- 자재 구매와 재고 변동을 작업 및 문서와 연결
- 회사·사업장·부서·사용자 권한에 따라 업무 데이터를 분리
- 온프라미스 운영 환경에서 회사별 초기 설정과 관리자 운영 지원

## 2. 사용자와 권한 범위

### 2.1 주요 사용자 역할 (Role)

| 역할 | 주요 책임 | 관리 대상 |
| --- | --- | --- |
| **ADMIN** | 시스템 전체 관리 | 모든 권한, 모든 데이터 |
| **MAINTENANCE_TECHNICIAN** | 설비 점검·작업 수행 | PM, WO, WP 작성·실행, 자재 출고 |
| **MAINTENANCE_MANAGER** | 유지보수 부서 관리 | PM, WO, WP 관리, 설비 관리, 결재 승인 |
| **PURCHASE_MANAGER** | 구매·자재 관리 | 구매오더, 자재 마스터 관리 |

### 2.2 권한 체계 (Permission Matrix)

모든 역할이 다음 권한을 가집니다:

- **읽기 (Read)**: 모든 자원에 대해 조회 권한 보유
- **결재 (Approval)**: 업무 프로세스에 정의된 결재 레벨에서 승인/반려 가능
- **게시판 (Board)**: 회사 단위 공지·자유게시판 접근 (권한 제약 없음)

각 역할별 생성·수정·삭제(CRUD) 권한:

| 권한 | PM | WO | WP | PO | 설비 | 자재 |
|---|---|---|---|---|---|---|
| **MAINTENANCE_TECHNICIAN** | C,R | C,R | C,R | R | R | R |
| **MAINTENANCE_MANAGER** | C,R,U,D | C,R,U,D | C,R,U,D | R | C,R,U,D | R |
| **PURCHASE_MANAGER** | R | R | R | C,R,U,D | R | C,R,U,D |
| **ADMIN** | C,R,U,D | C,R,U,D | C,R,U,D | C,R,U,D | C,R,U,D | C,R,U,D |

**범례**: C=작성, R=읽기, U=수정, D=삭제

### 2.3 문서 수정·삭제 규칙

- **작성자만 수정/삭제 가능**: 문서 작성자(owner)만 기본적으로 수정·삭제 권한
- **DRAFT 상태에서만**: 작성자가 수정·삭제할 수 있는 상태는 DRAFT(초안)일 때만
- **확정 후 잠금**: CONFIRMED(확정) 이상 상태의 문서는 수정·삭제 불가 (감사 추적 보존)
- **반려 시 재작성**: 결재 반려 시 문서를 DRAFT로 복원하지 않고, 작성자가 새 버전 작성

### 2.4 결재 시스템

결재는 **역할·권한 범위를 벗어난 공통 기능**으로 운영됩니다:

- 모든 사용자가 결재 가능 (권한 제약 없음)
- 결재 흐름은 **업무 프로세스(Work Process)에서 정의**
  - 각 프로세스(PM, WO, WP, PO 등)별로 다른 결재 라인 구성 가능
  - 레벨별 필요 역할 명시 (예: 레벨1=MAINTENANCE_MANAGER, 레벨2=SAFETY_OFFICER)
  - 조건부 결재 지원 (예: 금액 > 50,000원이면 추가 승인 필요)
- 사용자의 역할이 결재 레벨의 요구 역할과 일치하면 해당 레벨에서 승인 권한 획득

### 2.5 데이터 범위 (Context-based Access)

모든 사용자 접근은 소속 회사·사업장·부서 기준으로 자동 제한됩니다:

- **회사 단위 분리**: 회사별 데이터는 완전히 격리
- **사업장·부서 필터링**: 할당된 사업장·부서의 데이터만 조회
- **사용자·부서 관계**: 로그인 시 세션에 회사ID, 사업장ID, 부서ID, 사용자ID 저장
- **감사 추적**: 모든 상태 변경에 수행자·수행 시각·변경 내용 기록

## 3. 핵심 업무 영역

### 3.1 기준정보

- 회사별 사업장·부서·창고·사용자 관리
- 설비와 자재 마스터 관리
- 회사별 업무 유형·분류·상태 코드 관리
- 사용 중인 기준정보는 이력 보존을 위해 삭제보다 비활성화를 우선

### 3.2 예방점검 (PM)

- 설비별 점검 기록과 점검 항목 관리
- 점검일, 점검자, 점검유형, 결과와 판정 기록
- 설비 이력에서 관련 점검 결과 조회
- 점검 결과에 따라 후속 작업오더로 연결할 수 있는 기반 제공

### 3.3 작업오더 (WO)

- 설비 유지보수 작업의 계획·실적 관리
- 작업유형, 대상 설비, 작업내용, 일정, 작업자, 우선순위 관리
- 계획 단계와 결과 단계를 분리하여 저장·조회
- 작업 항목과 자재 사용, 첨부파일, 결재를 연결
- 완료된 업무는 삭제보다 상태·이력 보존을 우선

### 3.4 작업허가 (WP)

- 위험 작업의 허가 신청·검토·승인·완료 관리
- 작업 장소, 작업자, 책임자, 위험요인, 안전조치, 가스측정 등 기록
- 허가 문서를 인쇄 가능한 형식으로 제공
- 작업허가의 상태 전이와 승인 이력을 보존

### 3.5 구매와 자재 (PO)

- 자재 소요를 구매요청으로 등록
- 구매요청을 구매오더로 연결
- 거래처, 납기, 품목, 수량, 단가와 금액 관리
- 자재 기준가격과 실제 구매금액을 구분

### 3.6 재고

- 창고·자재별 현재고와 가용재고 관리
- 입고·출고·조정·이동 거래를 원장으로 기록
- 거래 사유, 수량, 금액, 발생일, 참조문서와 담당자 보존
- 작업오더·구매문서 등 관련 업무와 재고 거래 연결
- 월별 창고 마감과 마감 시점 재고 보존

### 3.7 결재·첨부·게시판

- 결재 문서 작성, 결재선 구성, 제출, 승인·반려 처리
- 결재 당시 결재자명·부서·직책을 기록하여 당시 상태 보존
- 업무 문서별 첨부파일 묶음과 파일 이력 관리
- 파일 다운로드·삭제는 원본 업무의 회사 범위와 권한을 따름
- 공지·자유게시판 등 회사 단위 게시글 관리

## 4. 공통 업무 원칙

1. 모든 업무 데이터는 회사 단위로 분리하고, 사업장·부서 범위가 필요한 경우 추가로 제한합니다.
2. 생성·수정·승인·삭제 등 상태 변경은 수행자와 시각을 남깁니다.
3. 업무번호와 참조관계를 통해 문서 간 연결을 유지합니다.
4. 승인·재고·구매·작업의 상태 변경은 유효한 이전 상태에서만 허용합니다.
5. 금액·수량·일자는 입력 범위와 형식을 검증하며, 화면 표시값과 저장값의 의미를 구분합니다.
6. 업무 기록을 임의로 제거하지 않으며, 필요한 경우 비활성·취소·반려·삭제표시로 상태를 보존합니다.
7. 오류 응답에는 사용자가 이해할 수 있는 메시지와 장애 추적용 식별자를 제공합니다.
8. **모든 변경 사항을 감사 로그(Audit Log)에 기록**하며, 변경된 필드명·이전값·변경값·수행자·수행시각을 저장합니다.

## 5. 주요 흐름

### 유지보수 흐름

```text
설비 등록 → 예방점검 기록 또는 작업요청 → 작업오더 계획
→ 필요 시 결재·작업허가 → 작업 수행 → 실적·자재 사용 기록 → 완료
```

### 구매·재고 흐름

```text
자재 소요 → 구매요청 → 구매오더 → 입고 → 재고 증가
작업 수행 → 자재 출고·조정 → 재고 감소 → 작업오더와 원장 연결
```

### 결재 흐름

```text
작성 → 결재선 구성(업무 프로세스 정의) → 제출 → 순서별 승인·합의·참조 → 승인 완료 또는 반려
```

## 6. 최초 설치와 회사 운영

제품은 데이터베이스가 준비된 온프라미스 환경에 설치합니다. 최초 운영 데이터는 회사별 bootstrap 절차로 생성합니다.

- 회사코드와 회사명을 등록
- 기본 사업장·부서 생성
- 최초 관리자 사용자와 로그인 인증정보 생성
- 관리자 기본 권한 부여
- 회사별 기본 코드·분류 생성

bootstrap은 회사 단위로 반복 실행할 수 있어야 하며, 이미 존재하는 회사나 관리자 정보를 임의로 덮어쓰지 않습니다.

## 7. 범위와 비범위

### 포함 범위

- 회사·조직·설비·자재 기준정보
- 예방점검, 작업오더, 작업허가
- 구매요청·구매오더·재고원장·월마감
- 결재, 첨부파일, 게시판, 인쇄용 업무문서
- 회사별 권한·데이터 범위와 최초 관리자 bootstrap
- **역할·권한 관리 및 감사 추적**

### 현재 비범위

- 외부 ERP·회계·구매 시스템과의 연동
- 모바일 전용 애플리케이션과 오프라인 동기화
- IoT 센서·실시간 설비 데이터 수집
- 고급 분석·예측정비·대시보드 BI
- 다국어 운영과 외부 고객용 포털

비범위 기능은 향후 연동 요구사항과 운영 우선순위를 검토하여 별도 제품 사양으로 확장합니다.

## 8. 완료 기준

제품 기능은 다음 조건을 만족할 때 업무 단위로 완료된 것으로 봅니다.

- 정상 흐름과 주요 예외 흐름이 정의되어 있습니다.
- 회사·사업장·부서·권한 범위가 업무에 맞게 적용됩니다.
- 상태 변경과 주요 참조관계가 이력으로 남습니다.
- 화면, API, 저장 데이터의 용어와 의미가 일치합니다.
- 주요 업무 규칙과 회사 간 데이터 격리가 테스트됩니다.
- 설치·초기 회사 및 관리자 생성 절차가 재현 가능합니다.
- **권한 검증과 감사 로그가 모든 CRUD 작업에 적용되어 테스트됩니다.**
